# 免费鸡蛋篮 · 收录、分级与发布规则

**规范版本：1.0（2026-10-08）**  
这是鸡蛋评级的**唯一判定来源**。所有自动任务、不同聊天与人工编辑在新增、核实、评级、改动状态、发布日报或超级鸡蛋专题前，**必须从 GitHub `main` 重新读取本文件**。不要依靠当前聊天记忆、早期日报、旧 JSON 简介或现存评级反向推断标准。

## 一、先决定能否收录（独立于等级）

本站优先收录**正规模型厂商 / 推理平台 / 能真正调用模型 API 的官方云服务 / 可信非营利公益 API**。

- 收录的价值必须是**真实可用的免费 AI 模型 API**：例如注册赠 API credits、免费 tokens、官方免费 API 调用额度；普通云赠金只有确认能实际用于指定 AI API 才能计入相应价值。
- 不收录普通商业中转站充值返利、积分营销、虚假美元、公司/融资/学生认证高门槛项目、需要大额先充值的优惠；公司特定活动与同平台个人可用的另一免费档要分开判断。
- 官方具体活动条款与**真实申请/领取入口**分别记录。活动页返回 404、跳转无关页面、搜索结果只有旧索引时，不能认定“现在可以领”。交叉参考近期社区反馈，但不能以社区传闻取代官方规则。
- 实际来源若只证明网页聊天免费、图片生成免费，不可当作 API credits。
- 必须注明赠额、支持的具体模型、个人资格/地区、**是否绑支付方式、是否需要先充值**、有效期与来源。用户未实际领取成功不能写成已经到账。

## 二、活动状态与价值分级是两个独立维度

| `status` | 含义 | `grade` 要求 | 默认列表 |
|---|---|---|---|
| `active` | 当期官方来源可验证，能通过公开入口申请 / 开通 | 仅此状态可评 `super` / `premium` / `normal` | 显示 |
| `pending` | 信息不足，仍需核实具体领取条件与有效性 | 必须为 `null` | 显示，但排在有效活动后 |
| `expired` | 有证据确认活动结束 / 明确失效 | 必须为 `null` | 显示，**始终放最后** |
| `unverifiable` | 多日真实核查仍无可靠的当前活动证据 / 原领取页消失 | 必须为 `null` | 转核查归档，不进入默认列表 |
| `excluded` | 资格/性质不符合本站收录范围 | 必须为 `null` | 转核查归档，不进入默认列表 |

**不要因为链接 404 直接声称官方已宣布活动结束**。可以把活动移入 `unverifiable`，保留旧链接和核查依据。只有官方有效期结束等明确证据才能改成 `expired`。

## 三、价值等级（仅对 `active`）

### 🥇 超级鸡蛋 `super`

以下条件**同时满足**才能评级：

1. 有官方**当前**赠额/免费配额规则、可访问的申请入口，适用个人用户；不是搜索缓存或旧活动。
2. 具备用户实际会使用的**高质量 AI API 模型**，如当前较强的通用、编程、推理模型；不能只凭“平台有强模型”推断赠金适用。
3. 明显高价值：原则上**至少 $20 可直接用于强模型 API 的新客 credits**；或者强模型**至少约 1000 万可用免费 tokens**等有相近实用价值的宽松配额；或者足以替代上述价值的长期、很高量免费调用。不同币种/不同模型 token 数不可生硬等价。
4. **个人低门槛**：无需企业/学生/融资资格、难通过的专项审批或实际先付钱才可领。普通支付卡身份验证可接受，但会降低评分；绑定卡和实际充值必须写清。
5. 限制不至于使宣传额度在常见场景实际不可用。如果给的是通用云服务 credits 却无法确认目标 AI API 能使用，**不能评超级**。

**禁止**为了每期都有超级鸡蛋而强行升级；当期没有则保留空榜。发布超级专题前还要再次验证领取入口与核心资格。

### ✨ 优质鸡蛋 `premium`

官方确认有效，有实用的模型 API；赠额/长期配额/模型质量明显优于普通试用，但未达到超级的高价值或低门槛要求。例：较实用的持续免费 API 配额、可调用强模型但额度有限、金额较高但支付/区域/AI 适用范围受限。

### 🥚 普通鸡蛋 `normal`

确认有真实免费 API 价值，但赠金较小、调用少、模型或权限较普通、需要绑卡或很短期限；仍值得列出让用户自己挑。

### 边界案例（须按具体条款处理）

- **$300 云试用金**：如不能直接抵扣目标模型 API，绝不只按面额评超级。
- **免费网页聊天**：不能代替 API 免费额度。
- **注册送 5 credits、绑卡再送 25**：分开记录，不把额外 25 写成免绑卡赠金。
- **宣传 1 亿 tokens，默认计划只有 1000 万**：只按已核实可用的默认额度评级，活动额外福利另行核实。
- **只查到 404 的 $150 活动**：进 `unverifiable`，不保留有效领取按钮，也不评超级。
- 同一平台多个独立方案可分条，但**同一活动不得重复收录、重复发布**。

## 四、质量分 `quality_score`（同等级内部排序）

每次新增或重新核实评级时，用下面的统一尺度解释或更新 **0–100** 的综合质量分：

| 评分维度 | 分值 | 判断重点 |
|---|---:|---|
| 真正可用的免费 API 价值 | 0–35 | 实际可用于目标模型的美元额度、token 数、长期调用量；不能看宣传面额 |
| 模型实用性与质量 | 0–25 | 强模型真实可用、通用/编程/推理实用性、可选模型范围 |
| 个人领取便利性 | 0–25 | 注册成功率、地区限制、手机号/实名/卡/预付款、等待审批 |
| 时效与使用限制 | 0–15 | 可领取期限、配额续期、日限速、到账与超额计费风险 |

`quality_score` 是**编辑综合判断，不是官方分数**；`grade` 由上面的明确资格与档位条件决定，不允许只看总分自动把普通升级超级。保存简洁 `grade_reason`，不得复制描述或重复免责声明。现存旧记录的历史分数可保留，但每次实质核实后应按本规则重新核对，不能没有证据就批量改分。

排序：`super` → `premium` → `normal` → `pending` → `expired`；同等级按 `quality_score` 从高到低，最后才按发现时间。核查归档项目只在单独栏目查看。

## 五、待核实的闭环

- 早报 / 晚报每天实际复核所有 `pending`，查官方活动条款、申请 URL、社区近期领取反馈、AI API 能否使用及绑卡资格。
- 更新 `last_reviewed_at`、`review_history`、`review_result`、`next_review_at`；**只有不同日期的真正复查才计次**。
- 证实有效就 `active` 并评分；明确结束 `expired`；资格不符 `excluded`；**连续三个不同自然日实际复查**仍查不到当期依据，就 `unverifiable` 并归档。任何归档项目如有新确凿证据可再开放。

## 六、发布前强制检查（早报、晚报、超级专题共用）

1. **重新读本文件和 `docs/CONTENT_GUIDE.md`**；不能凭不同聊天上下文自己改评级门槛。
2. 查最新数据并**先按状态规则和价值标准重新判断**；不满足 `active` 的鸡蛋不得生成 `grade`。
3. 如果要发布 `kind=super`：确认 `egg_id` 仍为 `active + super`、官方领取页可用、证据未过期；否则不发布/需更正已有专题。
4. 日报只叙述当天**真实新增、复核或状态变化**，旧记录不假冒今日活动。
5. 文案自然简短，优点与必要限制各说一次。不要重复套话、免责声明尾句；通用来源声明只写网站页脚。
6. 新版 `data/reports.json` 只保存最新早/晚报；**每期正式发布必须同步追加或修订 `data/report-archive.json`**，不得覆盖不同日期往期。
7. 校验 JSON、链接和字段；提交 GitHub 后必须确认站点部署对应当前数据且 READY 才可称“上线”。失败要直说。

**规范修改规则**：未来如果要变更评级，先修改本文件并提交 GitHub，再统一对照检查数据、页面说明和三个定时任务；不得单独通过聊天对某一自动任务下不同标准。
