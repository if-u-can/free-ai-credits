# 内容维护和自动更新约定

本文供项目维护者和自动更新任务使用，访客请阅读仓库根目录 README。

## 收录范围

- 包括官方 AI 模型厂商、推理平台、开发者 AI API 福利、可核实的非营利公益 API 服务。
- 不收录普通商业中转站的充值赠送、倍率优惠或促销信息。
- 禁止未经核实地把老活动描述为当前可领取。

## 鸡蛋数据

编辑 `data/eggs.json` 的 `eggs` 数组，每个对象建议提供：

- `id`: 不变的机器标识。
- `name`, `description`, `type`: 展示名、简介、来源类型。
- `status`: `pending`（待核实）、`active`（已核实有效）、`expired`（已失效）。
- `credits`: 金额 / 免费额度，说明是否要求充值或绑定卡。
- `models`: 可使用的具体模型名称数组，未知时标记待核实。
- `requirements`: 注册和领取门槛（地域、手机号、卡、邮箱、企业身份等）。
- `discovered_at`: 第一次发现该线索的时间；不要把随意整理时间伪装为发现时间。
- `verified_at`: 最近验证的时间，未知用 null。
- `verification_note`: 证据、查验方法以及存疑信息。
- `url`: 最好指向官方活动页面，不要贴无法证实的跳转。

更严格的收录建议逐步引入 `evidence_urls`、`expired_at`、`expiration_reason`、`last_seen_at` 等字段。

## 核实标准

1. 尽量找到官方活动页、定价页、文档或公开公告，避免仅凭二手转述。
2. 检查是否仍能申请，关注地区、绑卡、企业 / 学生认证、有效期与额度归零条件。
3. 没有足够证据时保持 `pending`。只有当当前活动与门槛有可验证来源时才设 `active`。
4. 查到活动结束时改为 `expired`，保留原有记录并补充原因。
5. 每次更新数据或报告都要保持 JSON 格式有效，并附来源。
6. 不应在网站暴露 API Key、邀请码私密凭证、账号信息。

## 早晚报

`data/reports.json` 包含 `morning` 与 `evening`：

- **早报**：轻快、元气、信息密集，重点讲新发现和当天优先领取的高价值项目。
- **晚报**：稍显抽象、吐槽式复盘，但信息准确，重点讲状态变化、失效和踩坑。
- 每条至少包含 `date`、`title`、`summary`。若没有最新可验证内容，就如实说明无更新，不得伪造每日新闻。

## 投稿流程

用户提交 GitHub Issue 后先核实，再由维护者合并到 JSON；公开投稿内容不应该直接写入“有效”列表。

## 发布机制

当前为静态 HTML + JSON，Cloudflare Pages 与 Vercel 均可托管。绑定 Git 后向默认分支提交即可触发构建。自动任务能否在无人值守时使用 ChatGPT 的 GitHub 写权限，需要单独验证，不能因普通会话写入成功就默认定时运行也能写入。
